# 混合精度量化评测（ONNX 复现）—— 实测报告

> 目的：验证「保留 LayerNorm/Softmax/激活等高敏感层为高精度、只量化矩阵乘」的混合精度策略效果，
> 并在**同等精度格式**下公平比较 Hadamard 变换的价值。
> 数据：ImageNet-1K val，短边 resize 224 + center crop；n_calib=100、n_eval=300；标签映射对齐 dapa_repro.py

---

## 一、完整结果

| 配置 | FP32 基线 | 量化后 | 掉点 | 预测一致率 |
|---|---|---|---|---|
| 无 Hadamard · **全 INT8**（MinMax） | 56.33% | 42.00% | **−14.33 pp** | 53.0% |
| 无 Hadamard · **全 INT8**（KLD） | 56.33% | 43.33% | **−13.00 pp** | 50.0% |
| 无 Hadamard · **混合精度**（MatMul/Conv INT8 + KLD） | 56.33% | 54.33% | **−2.00 pp** | 80.7% |
| **有 Hadamard · 混合精度**（同上） | 56.33% | **55.33%** | **−1.00 pp** | 78.0% |
| 有 Hadamard · 全 INT8（MinMax） | 56.33% | 41.00% | −15.33 pp | 50.0% |

混合精度配置：`op_types_to_quantize = [MatMul, Conv, Gemm]`，即
**LayerNorm（ReduceMean/Sub/Pow/Sqrt/Div/Mul/Add）、Softmax、GELU（Sigmoid）、残差 Add 全部保持 FP32**。

---

## 二、三条核心结论

### 1. 纯 INT8（连敏感层一起量化）会崩 —— 掉 13~15 pp
无论是 MinMax 还是 KLD 校准，只要把 LayerNorm/Softmax/激活一起量化，精度从 56.33% 掉到 41~43%，
预测一致率仅 50%（相当于随机翻转一半）。**这正是 CLIP 「极端激活值」的特性所致。**

### 2. 保留敏感层为高精度是**必需**的 —— 掉点从 13pp 降到 2pp
只量化 MatMul/Conv、其余留 FP32 后：
- 掉点 **−13.00 pp → −2.00 pp**
- 预测一致率 **50.0% → 80.7%**

**这个 2pp 与 Icraft 板上实测（官方 66.6% → 板上 64.9%，约 −1.7 pp）量级吻合** ✓
说明「混合精度 + 只量化矩阵乘」才是 Icraft 实际能跑出 64.9% 的原因，
而「全 INT8」在 PC 模拟里是灾难性的 —— 也解释了为什么之前 ORT 全 INT8 复现出 42%（与板上 64.9% 差 20pp）。

### 3. 同等精度格式下，**Hadamard 把掉点减半**（关键结论）

| | 无 Hadamard | 有 Hadamard | Hadamard 增益 |
|---|---|---|---|
| 混合精度掉点 | −2.00 pp | **−1.00 pp** | **+1.00 pp** |
| 量化后绝对精度 | 54.33% | **55.33%** | **+1.00 pp** |

**这是干净的同条件对比**：两条链路 FP32 基线相同（56.33%），量化策略完全相同，
唯一变量就是有没有 Hadamard 旋转 → **Hadamard 确实抑制了 INT8 量化掉点，增益约 1 pp。**

与项目汇报的 64.9% → 66.4%（+1.5pp）方向一致、量级相近；
差异在于汇报数据中「有 Hadamard」用的是 **BF16** 执行（`qdtype="bf16"`），
而「无 Hadamard」是 **INT8**（`qdtype="int8"`），混入了精度格式变量。
本实验证明：**即使两者都用 INT8，Hadamard 仍有约 1 pp 的真实增益。**

---

## 三、与 Icraft 实际模型精度的交叉验证

从 Icraft 模型 json 逐 op 读出的实际执行格式：

| 模型 | 编译配置 | 实际执行格式 |
|---|---|---|
| 无 Hadamard（完整 `clip_vit_b32_ZG`，926 ops） | `img.toml`：`qdtype=int8` | **INT8 99.6%** |
| 有 Hadamard（`vit_seg_pre_ZG`，24 ops） | `qdtype=bf16` | BF16 79% + TF32 21% |
| 有 Hadamard（`vit_seg_post_ZG`，946 ops） | `qdtype=bf16` | **BF16 98.2%**，INT8 = 0 |
| 有 Hadamard（新编 `vit_seg_post_int8`，953 ops） | `qdtype=int8`（本次新增） | **INT8 97.7%** |

即：板上「有 Hadamard」的 66.4% 其实是 **BF16** 跑出来的，
BF16（8位指数+7位尾数）动态范围同 FP32、不会因离群点溢出，因此精度天然高于 INT8。

---

## 四、汇报口径建议（更新版）

> 图像编码器采用混合精度量化（仅 MatMul/Conv 量化至 INT8，LayerNorm/Softmax/激活保持高精度）。
> 在 ImageNet-1K 上：FP32 56.33% → 混合精度 INT8 **54.33%**（−2.0 pp）；
> 引入 Hadamard 变换后提升至 **55.33%**（−1.0 pp，掉点减半），证明 Hadamard 旋转有效抑制了 INT8 量化损失。
> 若不加区分地全 INT8 量化（含 LayerNorm/Softmax），精度将崩溃至 43.33%（−13.0 pp）。

关于 Hadamard 的增益：同等 INT8 混合精度下约 **1.0 pp**（掉点从 2.0pp 减半到 1.0pp），为控制变量后的对比结果。

## 五、脚本

| 脚本 | 说明 |
|---|---|
| `eval_quant_impact.py` | 量化评测（`--optypes` 控制混合精度、`--calib entropy/minmax`） |
| `gen_pre_int8_qtset.py` | seg_pre INT8 校准集（归一化 NHWC float32） |
| `gen_post_int8_qtset.py` | seg_post 四输入 INT8 校准集 |
| `compile_vit_seg_pre_int8.toml` / `compile_vit_seg_post_int8.toml` | 新增 INT8 编译配置 |

复现命令：
```bash
# 无 Hadamard · 混合精度
python eval_quant_impact.py --model orig --calib entropy --optypes "MatMul,Conv,Gemm" --n-eval 300
# 有 Hadamard · 混合精度
python eval_quant_impact.py --model hada --calib entropy --optypes "MatMul,Conv,Gemm" --n-eval 300
# 全 INT8（对照）
python eval_quant_impact.py --model orig --calib entropy --optypes "" --n-eval 300
```
